# Module 12 (Integration Hub) — Production Readiness Checklist

Compiled at the close of Phase 8, §7's final build phase. Cross-references every ADR/design doc produced across all eight phases rather than re-deriving them here.

## Delivered in this build

- [x] **Schema** (Phase 1, ADR-0136): `IntegrationConnector`/`FieldMapping`/`SyncJob`/`WebhookSubscription`/`WebhookDelivery`/`ProviderRateLimitConfig`/`FieldAuthorityPolicy`, RLS on every tenant-scoped table, composite FKs denormalizing `tenant_id`.
- [x] **Connector framework + Vault** (Phase 2, ADR-0134/0137): real HashiCorp Vault KV v2 client, OAuth and non-OAuth credential intake, OAuth callback flow, `assertNoRawCredentialMaterial` credential-shape guard, batch-runner and streaming-relay bases.
- [x] **First batch adapter** (Phase 3, ADR-0138): `WorkdayAdapter` - field mapping, dry-run-then-commit against Module 02's real bulk-import.
- [x] **Field authority conflict detection** (Phase 4, ADR-0139): reuses Module 02's own bulk-import dry-run diff.
- [x] **Provider rate limiting** (Phase 5, ADR-0140): proactive token-bucket throttle + reactive backoff, all 10 researched providers' real limits seeded.
- [x] **First streaming adapter + full relay path** (Phase 6, ADR-0141): `GenesysCloudAdapter`, `BackpressureQueue`, real HMAC-signed forwarding to Module 05's `activity-events` endpoint, idempotent dedupe.
- [x] **Remaining connector providers** (Phase 6b, ADR-0142/0143): SAP SuccessFactors, ADP, Salesforce (batch); NICE CXone, Five9, Talkdesk (streaming). Avaya explicitly deferred.
- [x] **Webhook framework** (Phase 7, ADR-0144): `WebhookSubscription`/`WebhookDelivery` CRUD, HMAC-signed outbound dispatcher with retry/auto-disable, NATS publish (`agno.integration_hub.sync_job.completed.v1`) fanning out from `SyncJobsService.complete()`.
- [x] **RBAC + connector health dashboard** (Phase 8, ADR-0145): `createConnector`/`createWebhookSubscription` gated via remote-JWKS JWT verification; `connectorHealth`/`connectorsHealth` aggregating queries; `integration_hub_rbac_denials_total`/`integration_hub_webhook_deliveries_total` metrics.
- [x] Real end-to-end verification throughout: real Postgres, real Vault, real NATS, real sibling services (Module 02 bulk-import, Module 05 activity-events) wherever they exist in this monorepo; real local fake servers standing in for external providers with no real credentialed tenant available in this environment. 61 unit tests + 51 integration tests, `typecheck`/`lint` clean as of this phase's own final run.

## Explicitly NOT done here (needs a different owner, or a later phase, before go-live)

- [ ] **Avaya Aura Contact Center/CMS** (ADR-0142) — needs a licensed AES/TSAPI environment this build environment doesn't have; Avaya Experience Platform (cloud) is architecturally buildable but was never in this module's own §7 provider list.
- [ ] **ADP's real mTLS handshake** (ADR-0143) — credential shape (`clientCertPem`/`clientKeyPem`) is correct and Vault-stored; the actual TLS client-certificate wiring needs `undici`'s own `Agent`/`Dispatcher` API, not built this session. `AdpAdapter` fails closed (`missing_mtls_material`) rather than silently degrading.
- [ ] **Rate limiter state is single-instance, in-process** (ADR-0140) — running more than one active cron-ticking instance of this service would let each instance's token bucket drift independently of the others' real consumption. Needs a shared (Redis-backed) store if this service is ever run with >1 active replica.
- [ ] **Undocumented streaming event wire shapes** (NICE CXone, Five9, Talkdesk, Phase 6b design doc) — best-effort, structurally-verified-only shapes; no vendor-published schema exists in any researched source for these three providers' actual real-time payloads. A real tenant integration may need adjustment once a real payload is seen.
- [ ] **Only one webhook event type exists** (`sync_job.completed`, ADR-0144) — no per-provider or per-connector-type granularity; a consumer needing that must cross-reference `connectorId` against the `connectors` query themselves.
- [ ] **No RBAC revocation check** (ADR-0145) — a revoked-but-not-yet-expired JWT still passes `AccessTokenGuard`; mitigated by short access-token TTLs at the issuer (core), not solved in this service. Same disclosed trade-off ai-layer-service's own ADR-0130 already accepted platform-wide.
- [x] ~~RBAC gates only two mutations~~ — **partially closed by ADR-0160**: `RelayController`'s `relay/start`/`relay/stop`/`relay/status` and `BatchSyncController`'s `:id/sync` had *zero* guards of any kind before ADR-0160 (not even the two-mutation baseline above) despite `relay/start` opening a live external OAuth/WebSocket session and `:id/sync` running a real batch sync, both using this connector's own Vault-referenced credential — the actual highest-risk unauthenticated surface in this module, undiscovered until this ADR. All four now require `integration_connector:write`/`:read` via the same guard trio. Every *other* query/mutation in this module's GraphQL schema still remains on the `x-tenant-id` header-trust placeholder (ADR-0014) — expanding RBAC to the rest of the schema is still a real, explicit scope decision for a future phase.
- [ ] **A live NATS broker was available and exercised in this environment** (unlike some other modules' own readiness checklists) — this module's NATS publish (`agno.integration_hub.sync_job.completed.v1`) *was* verified against a real running NATS/JetStream instance in this build, including a real subscriber receiving the message. Flagged here only because a future deployment environment's own NATS reachability is still an operational prerequisite, not because it's unverified in this build.
- [ ] **No connector-level or webhook-subscription-level rate limiting on GraphQL mutation frequency** — a tenant admin can call `createConnector`/`createWebhookSubscription` as fast as their access token allows; no per-tenant write throttle exists anywhere in this module.
- [ ] **Multi-instance/restart-safe streaming relay ownership** (Phase 2 design doc's own original disclosure, never revisited) — `StreamingRelayService.liveSessions` is process-local, in-memory state; a process restart loses track of any live session's handle.
