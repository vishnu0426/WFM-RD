# Module 09 Phase 4 Production Readiness Checklist

Honest split between what this phase's code actually delivers and what is genuinely a later phase's (or a wholly unowned) gap. This phase's own design doc records five real bugs caught by actually running real GraphQL/REST requests against real seeded data - not review guesses - all fixed and covered by regression tests.

## Delivered in this phase (application code)

- [x] `1700007000000-DashboardNameAndPlatformDefaultMetrics.ts`: `saved_report.name` (`NOT NULL`, no default needed - zero pre-existing rows), six platform-default `MetricDefinition` rows (`adherence_trend`, `forecast_accuracy_mape`, `scheduled_hours`, `overtime_hours`, `approved_leave_days`, `attrition_terminations`), each `estimated_cost_tier = 'cheap'`/`validated_at = now()` set directly (platform-authored, not routed through Phase 5's tenant-authored dry-run gate).
- [x] `MetricQueryEngineService`: looks up a `MetricDefinition` (tenant override or platform default), validates its `calculationDefinition` against `SOURCE_VIEW_REGISTRY`'s hardcoded whitelist before building any SQL, reads `analytics_mv.mv_*` **only** via `ANALYTICS_APP_REPLICA_PG_POOL` (never a live cross-module query, §3), returns `dataAsOf` from `mv_lineage` on every result. Backs both GraphQL's `metricQuery`/`executiveSummary` and `GET /v1/analytics/metrics/{metricName}` - one implementation, two transports.
- [x] `DashboardService`: `createDashboard`/`getDashboard`/`listMyDashboards`, every method via `withTenantConnection` (this platform's established RLS-scoping convention for TypeORM CRUD, confirmed by research before use, not assumed). `createDashboard` rejects an unknown `metricId` and a metric tiered `'expensive'` - both verified directly against real data, not just unit-mocked.
- [x] This service's first GraphQL surface (`AnalyticsGraphQLModule`): `dashboard`/`myDashboards`/`createDashboard`/`metricQuery`/`executiveSummary`, a hand-rolled `JsonScalar` (own copy, no new dependency), `formatGraphQLError` mapping `DomainError` → GraphQL error shape.
- [x] `GET /v1/analytics/metrics/{metricName}` (§4.2/§3's BI-connector surface) - REST, same query engine as GraphQL.
- [x] `X-Actor-Id` (own copy of ADR-0084's pattern) - `TenantContextService.requireActorId()`, lowercase-normalized same as `X-Tenant-Id`.
- [x] `DomainErrorFilter` GraphQL-context bailout; `HttpMetricsInterceptor` multi-transport upgrade (`Query.metricQuery`/`Mutation.createDashboard`-shaped route labels for GraphQL, unchanged REST labels).
- [x] Five real bugs found and fixed via actual GraphQL/REST requests against real seeded data (not code review): a missing `saved_report.name` column, two GraphQL code-first reflection failures (string-literal-union field, nullable `Date` field - both need an explicit `@Field(() => X)`), a `class-validator` whitelist gap on two jsonb input fields (`@IsObject()` needed alongside `@Field(() => Object)`), a Postgres parameter-type-inference error (`$3` reused inside `+ interval` arithmetic), and an off-by-one bug that silently dropped a genuine result whenever fewer rows existed than the requested page size - all five now covered by regression tests.
- [x] Unit test coverage: the migration's shape (name column, six seeded metrics each validated against `SOURCE_VIEW_REGISTRY`), `MetricQueryEngineService` (tenant-override-vs-platform-default precedence, whitelist rejection, dimension-filter scoping, the off-by-one fix, `dataAsOf` sourcing, `executiveSummary`'s org-unit-gated inclusion/exclusion rules, cost-tier metric labeling), `DashboardService` (metric-not-found/expensive-metric rejection, creator-only authorization, `listMyDashboards`' real per-dashboard widget fetch), `TenantContextService`/`Middleware`'s new `actorId` handling - all mocked-pool/mocked-manager, no live Postgres required (97 tests total, up from 60 in Phase 3).
- [x] Verified against a real local Postgres, the same real streaming replica Phase 2 stood up, and real HTTP/GraphQL requests: `GET /v1/analytics/metrics/scheduled_hours?costCenter=CC-100` returns the real seeded value with `dataAsOf`; `createDashboard`→`dashboard(id)`→`myDashboards` round-trips correctly; a different actor cannot read another actor's dashboard (`DASHBOARD_NOT_FOUND`); a different tenant cannot read across tenants (RLS); the expensive-metric guard was exercised by temporarily tiering a real metric `'expensive'` and confirming rejection, then reverting; the full app boots with the GraphQL surface registered and serves `/graphql`/`/healthz`/`/readyz`/`/metrics`.

## Explicitly NOT done here (needs a later phase, or is a real, currently-unowned gap)

- [ ] **Module 01 RBAC/ABAC integration for `SavedReport.sharedWith` (§2.3 rule 3).** No client for Module 01's identity/RBAC service exists in this service. `getDashboard`/`myDashboards` authorize on `createdBy` only - a dashboard's creator can always see it; anyone it was meant to be *shared with* currently cannot, at all. This is a real, disclosed capability gap with no phase in this module's own §8 build-phase list currently assigned to close it - flag for product/architecture discussion, not quietly deferred.
- [ ] **`createScheduledExport` and the async export job.** Phase 6.
- [ ] **`askAnalyticsQuestion`.** Phase 7.
- [ ] **The custom-metric dry-run validation/cost-tiering pipeline for tenant-authored `MetricDefinition` rows.** This phase's six metrics are platform-authored and bypass that gate by design; a tenant creating their *own* `MetricDefinition` today would get no validation and no cost tier at all (the column stays `NULL`) until Phase 5 exists. No tenant-authored metric creation path exists yet regardless (no mutation for it) - this is a forward-looking gap, not a live one.
- [ ] **Rate limiting on the REST BI connector or the GraphQL surface.** Same explicit non-goal already stated platform-wide for every prior module.
- [ ] **The §0.5 per-query-pattern SLOs (dashboard p95 < 1s, ad hoc report p95 < 5s) are not measured** - no load test has run against this phase's surface yet. Phase 8.
- [ ] **The consistency-check job (§2.3 rule 4).** Still not built - no materialized view has been checked against a fresh source read at any point in this module's build so far. Phase 8.
